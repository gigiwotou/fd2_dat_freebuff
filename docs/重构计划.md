## 二、重构优先级

### 🔴 第一阶段：核心架构重构（必须立即执行）

#### 1.1 废弃旧架构，统一使用三层状态机

**现状问题**:
- 存在两套架构并存：旧架构 (`fd2_game_core.c` + `fd2_states.c`) 和新架构 (`fd2_state_machine.c`)
- 主循环使用 `fd2_game_run()` 而非 `fd2_state_machine_run()`

**必须做的修改**:
1. **标记废弃旧架构文件**:
   - `fd2_game.h` - 保留类型定义，废弃状态枚举
   - `fd2_game_core.c` - 废弃 `fd2_game_run()`
   - `fd2_states.c` - 废弃所有 `state_*_enter/update/exit` 函数
   - `fd2_states_intro.c` - 改为场景实现
   - `fd2_menu.c` - 改为场景实现
   - `fd2_continue.c` - 改为场景实现
   - `fd2_cutscene.c` - 改为场景实现
   - `fd2_battle*.c` - 改为场景实现

2. **修改main.c使用新架构**:
   ```c
   // 旧代码
   fd2_game_t game;
   fd2_game_init(&game, ...);
   fd2_game_run(&game);
   
   // 新代码
   fd2_state_machine_t sm;
   fd2_state_machine_init(&sm);
   fd2_register_all_scenes(&sm);
   fd2_state_machine_run(&sm);
   ```

3. **迁移现有场景逻辑**:
   - 将 `state_intro_enter/update/exit` 迁移到 `scene_X_init/exit`
   - 将 `state_menu_enter/update/exit` 迁移到 `scene_Y_init/exit`
   - 以此类推...

**预计工作量**: 2天  
**影响范围**: 📦 全局  
**验证标准**: 游戏能正常运行，所有现有场景功能正常
