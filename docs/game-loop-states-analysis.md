# FD2 游戏循环状态机分析

> 来源: IDA Pro MCP 逆向分析 FD2.EXE
> 日期: 2026-05-02

---

## 一、概述

FD2 游戏使用**三层状态机**结构：
- **外层状态**（n2_0）：控制游戏主阶段（输入处理/过渡/战斗场景）
- **内层状态**（n17）：控制具体场景类型（地图索引）
- **模式状态**（n44）：控制输入处理模式（移动/事件/菜单等）

## 二、主循环结构

### main() 函数 (0x25BF4)

```
初始化
  ├── 音频系统初始化 (XMIDI + Sample)
  ├── 资源加载 (FDOTHER.DAT #1-6, FDTXT.DAT)
  └── 内存分配

主循环 (while 1)
  ├── sub_25977(音乐) - 播放音乐
  └── sub_25EBB() - 游戏入口函数
       ├── 返回值 0: 进入主循环 (sub_117E7)
       ├── 返回值 1: 加载存档，进入场景
       └── 返回值 -1: 退出游戏
```

### 主循环状态切换

```c
while (1) {
    v11 = sub_25EBB(...);
    if (v11 == 0) {
        // 状态 0: 主输入处理循环
        do {
            v11 = sub_117E7(...);
            
            if (n2_0 == 1) {
                // 状态 1: 过渡/加载
                sub_22E5C(...);
                n2_0 = 0;
            }
            else if (n2_0 == 2) {
                // 状态 2: 战斗/场景
                funcs_25E23[n17](...);
                if (!sub_26152()) {
                    funcs_25E3A[n17](...);
                    sub_25977(byte_51E63[n17], ...);
                }
                n2_0 = 0;
            }
        } while (!v11);
    }
    else if (v11 == 1) {
        // 加载存档后进入场景
        byte_51AAC = 0;
        sub_26152();
        if (!v16) {
            funcs_25E3A[n17](...);
            sub_25977(byte_51E63[n17], ...);
        }
        byte_51AAC = 1;
    }
    // v11 == -1: 退出游戏
}
```

### 状态 0：主输入处理循环

## 四、sub_25EBB 游戏入口函数

### 功能

`sub_25EBB` 是游戏的主要入口点，负责：
1. 播放开场动画 (`sub_1F894`)
2. 处理菜单选择 (Start/Continue)
3. 加载存档数据
4. 初始化场景状态

### 执行流程

```
sub_25EBB
  ├── sub_1F894()  // 播放开场动画
  ├── 返回值判断:
  │    ├── 0: 用户选择 Start (新游戏)
  │    │    ├── n17 = 0  // 设置场景索引
  │    │    ├── funcs_25E3A[0]()  // 开场剧情
  │    │    └── sub_25977(byte_51E63[0], ...)  // 播放音乐
  │    ├── 1: 用户选择 Continue (加载存档)
  │    │    ├── 加载 FD2.SAV
  │    │    ├── sub_29BCB() 解析存档
  │    │    ├── 恢复场景状态 (n17, n6_6, byte_51AAB 等)
  │    │    └── sub_26152() 初始化场景
  │    └── 其他: 播放对应音乐
  └── 返回 v11 (0=新游戏, 1=加载存档, -1=退出)
```

### 存档加载逻辑

## 五、sub_26152 场景初始化函数

### 功能

检查并初始化当前场景，决定场景是否继续或结束

### 执行流程

```
sub_26152
  ├── 释放旧资源 (dword_53A45, dword_53A55, n7 等)
  ├── 加载图标资源 (fdicon.b24)
  ├── 判断 byte_523E7[n17]:
  │    ├── 1: 特殊场景处理
  │    │    ├── sub_1956B() 加载场景
  │    │    ├── sub_15F84() 显示对话
  │    │    └── sub_2AF28() 等待交互
  │    └── 0: 通用场景处理
  │         ├── sub_4E809() 加载地图
  │         ├── sub_2EB9F() 渲染场景
  │         └── 按键检测循环
  └── 返回是否继续 (n5 != 2)
```

## 九、总结

1. **三层状态机结构**: 外层 (n2_0) → 内层 (n17) → 模式 (n44)
2. **三个主要状态**:
   - **状态 0** (sub_117E7): 主输入处理，处理角色移动、事件触发、战斗等
   - **状态 1** (sub_22E5C): 场景过渡，加载新资源并渲染
   - **状态 2** (funcs_25E23 + sub_26152 + funcs_25E3A): 战斗/场景处理
3. **函数指针表**: 4 个主要函数表用于不同场景和事件处理
4. **存档系统**: 使用 FD2.SAV 保存游戏状态，包含地图数据、场景索引、标志位等
5. **音频系统**: 支持 XMIDI 音乐和数字音效，通过不同 handle 管理
