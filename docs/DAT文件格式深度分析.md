# DAT文件格式深度分析

## 1. 文件头6字节分析

### 发现
**所有DAT文件的前6字节都是: `4C 4C 4C 4C 4C 4C`**

转换为ASCII: `LLLLLL`

### 含义推测
- 这是**填充字节**或**占位符**
- `0x4C` ('L') 可能是某种标记或填充值
- 程序在读取时直接`fseek(_rb_, 6, 0)`跳过，**从不读取或使用这6字节**
- 这可能是早期开发时预留的文件头空间，但实际未使用

### 不同文件对比
| 文件名 | 文件头 | 说明 |
|--------|--------|------|
| FDOTHER.DAT | 4C4C4C4C4C4C | 标准DAT文件 |
| FDTXT.DAT | 4C4C4C4C4C4C | 标准DAT文件 |
| ANI.DAT | 4C4C4C4C4C4C | 标准DAT文件 |
| BG.DAT | 4C4C4C4C4C4C | 标准DAT文件 |
| PASS.DAT | **436F6D706172** | 不同！可能是自定义格式 |

**PASS.DAT是特例**：文件头为`436F6D706172` = `Compar` (ASCII)，可能是"Compare"或"Company"的缩写，说明它不是标准DAT格式。

## 2. DAT文件标准格式

```
偏移0-5:    文件头 (6字节，固定为"LLLLLL")
偏移6开始:  索引表
           - 每个索引项4字节 (32位小端整数)
           - 索引N表示第N个数据块的起始偏移
           - 最后一个索引表示文件末尾
索引表之后: 数据块区域
```

### 计算公式
```
索引表位置: offset = 索引号 * 4 + 6
数据块N的起始位置: indices[N]
数据块N的大小: indices[N+1] - indices[N]
```

## 4. 代码中文件头的使用

通过反编译分析，代码中对文件头的处理:

```c
// sub_111BA - 核心加载函数
fseek(file_handle, 4 * index + 6, SEEK_SET);  // 直接跳过6字节，从偏移6开始读索引

// sub_11019 - 图标加载函数  
fseek(file_handle, 6, SEEK_SET);  // 直接跳过6字节

// sub_20421 - ANI动画播放
fseek(file_handle, 4 * index + 6, SEEK_SET);  // 同样跳过6字节
```

**结论**: 
- 6字节文件头**从未被读取或使用**
- 程序直接跳过，从偏移6开始读取索引表
- 可能是预留空间或格式兼容性用途

## 5. 数据块类型识别

### 5.1 RLE压缩图片
**特征**:
- 前2字节: 宽度 (16位小端)
- 第3-4字节: 高度 (16位小端)
- 后续: RLE压缩的像素数据

**识别公式**:
```c
if (width > 0 && width <= 2000 && height > 0 && height <= 2000)
    // 可能是RLE图片
```

### 5.2 调色板数据
**特征**:
- 大小 = 768字节 (256色 * 3字节)
- 每个字节值范围 0-63 (6位颜色)

### 5.3 AFM动画文件
**特征**:
- 以`41464D20` ("AFM ")开头
- 包含版权信息字符串

### 5.4 嵌套DAT文件
**特征**:
- 以`4C4C4C4C4C4C` ("LLLLLL")开头
- 内部有完整的DAT结构

### 5.5 LMI音频数据
**特征**:
- 以`4C4D4931` ("LMI1")开头
- 可能是压缩的音频数据

## 7. 总结

1. **文件头6字节**: `LLLLLL` (0x4C重复6次)，**从未被使用**，直接跳过
2. **索引表**: 从偏移6开始，每项4字节小端整数
3. **数据类型**: RLE图片、调色板、AFM动画、LMI音频、嵌套DAT
4. **ANI.DAT特殊性**: 数据块是完整的AFM动画文件，有版权信息
5. **PASS.DAT特殊性**: 文件头不同，可能是自定义格式
