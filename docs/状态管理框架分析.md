# 状态管理框架分析

## 1. 状态管理概述

游戏采用多层次状态机架构，通过全局变量和函数指针数组管理游戏状态。核心状态管理函数包括 `sub_25EBB`（主状态管理器）和 `sub_25977`（场景/音乐状态切换器）。

## 3. 状态机架构

### 3.1 状态层级结构

游戏状态分为三层：
- **主场景层 (n17)**: 控制游戏大场景（如主菜单、战斗、地图等）
- **子场景层 (n16_1)**: 控制场景内的子选项或状态
- **菜单选择层 (n5)**: 控制当前选中项索引

### 3.2 状态转换流程

```
游戏启动
    ↓
sub_1F894() - 初始化和主菜单显示
    ↓
sub_25EBB() - 主状态管理器
    ↓
┌─────────────────────────────────────┐
│  状态检查循环                        │
│  ├─ 加载存档 (FD2.SAV)              │
│  ├─ 解析场景数据                     │
│  ├─ 调用场景处理函数 (funcs_25E3A)   │
│  ├─ 切换场景音乐 (sub_25977)        │
│  └─ 等待输入并处理状态转换          │
└─────────────────────────────────────┘
    ↓
状态转换或退出
```


```
4. 遍历场景数据块 (每个2600字节)

6. 调用 sub_26996() 处理场景数据
7. 进入场景交互循环
```

## 10. 分析要点

1. **状态管理模式**: 游戏使用全局变量存储状态，通过函数指针数组实现状态分发
2. **场景切换机制**: 通过 sub_25977() 管理场景音乐切换，通过 sub_26152() 处理场景交互
3. **存档系统**: 使用 FD2.SAV 存储游戏状态，包含场景索引、选项数量、进度等关键信息
4. **输入处理**: 使用 BIOS 中断 (int386) 读取键盘输入，通过 switch 语句分发到不同处理逻辑
5. **动画系统**: 场景切换时播放波纹/扩散动画效果，增强视觉体验
6. **音乐控制**: 支持多种音乐播放模式，包括循环播放和一次性播放

### 11.6 完成状态含义

```c
n2_0 = 0;  // 场景未完成，继续游戏
n2_0 = 1;  // 场景完成，可以进入下一场景
```

### 11.7 场景类型分类

1. **简单过渡场景**（11个）
   - 场景0, 2-8, 10, 13, 23
   - 无需特殊条件，直接进入下一场景

2. **收集类场景**（3个）
   - 场景1：检查对象5-10是否全部交互
   - 场景12：批量检查12个条件
   - 场景19：批量检查40+个条件

3. **条件触发场景**（12个）
   - 场景11, 14, 15, 20, 21, 24, 25, 26, 27：单条件检查
   - 场景9, 20, 25：双条件检查
   - 场景17, 22：多条件组合

4. **进度依赖场景**（1个）
   - 场景18：依赖n999进度值

5. **多阶段场景**（2个）
   - 场景17, 22：设置n2_0=1或n2_0=2
