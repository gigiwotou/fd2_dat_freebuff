# FD2.SAV 存档文件格式分析

> 基于IDA Pro MCP反汇编分析，地址范围: FD2.EXE

## 概述

FD2.SAV是游戏的存档文件，包含两类存档：
1. **营地存档**：共享数据区，所有存档槽位共用同一块内存区域（前12501字节）
2. **战场临时存档**：4个独立槽位，每个槽位2600字节，用于保存战场进度

**重要发现**：
- 存档选择菜单（sub_29BCB）中n2_3变量范围是0-3，说明有**4个存档槽位**
- 战场存档位置计算公式：`12587 + 2600 * n2_3`
- 所有存档槽位共享前12501字节的营地数据区
- 校验和位于文件末尾4字节（22983-22986）

## 加密与校验机制

### 校验和算法 (sub_4DF09)

```c
int sub_4DF09(_BYTE *a1, int n22987)
{
  int v3 = n22987 - 4;  // 排除最后4字节校验和
  int v4 = 0;
  int v5 = 0;
  do {
    LOBYTE(v5) = *a1++;
    v4 += v5;
    --v3;
  } while (v3);
  return v4;
}
```

**说明**: 将前22983字节逐个累加（只取每个字节的低8位），结果存储在文件偏移22983-22986处（4字节DWORD）

### 加密/解密算法 (sub_4DF28)

```c
char sub_4DF28(char *a1, int a2)
{
  char *v2 = a1;
  char *v3 = a1;
  __int16 n165 = 165;  // 初始密钥 0xA5
  do {
    v6 = *v2++;
    n165 = ROL2(n165 - 28652, 3);  // 0x7014
    result = n165 ^ v6;
    *v3++ = result;
    --a2;
  } while (a2);
  return result;
}
```

**说明**: 
- 初始密钥: 165 (0xA5)
- 每次迭代: `key = ROL((key - 0x7014), 3)`
- 加密解密使用同一函数（XOR特性）

## 文件数据布局

```
偏移范围              大小        内容
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

4771 - 12450         7680字节    营地角色数据 (共享, 96×80字节)
12451 - 12482        32字节      营地图标缓存 (共享, FDICON.B24)
12483 - 12500        18字节      营地游戏状态变量 (共享)
12501 - 12586        86字节      未使用/填充
12587 - 15186        2600字节    战场临时存档 - 槽位0

17787 - 20386        2600字节    战场临时存档 - 槽位2

22983 - 22986        4字节       校验和 (覆盖整个文件的累加和)
```

**总计**: 22987字节

### 重要说明

1. **营地存档数据是共享的**：前12501字节是所有4个存档槽位共享的区域。当玩家选择不同的存档槽位时，营地数据区域会被重新加载和覆盖。

2. **战场临时存档是独立的**：从偏移12587开始，有4个独立的2600字节区域，每个槽位对应一个战场存档。

3. **校验和验证**：校验和位于文件末尾4字节（22983-22986），是对前22983字节的累加和校验。

## 详细结构定义

### C语言结构体

```c
typedef struct {
    // ========== 共享营地数据区 (0 - 12500) ==========
    
    // 偏移 0-2210 (2211字节) - 营地地图数据
    unsigned char camp_map_data[2211];
    
    // 偏移 2211-4770 (2560字节) - 营地战场队伍数据
    unsigned char camp_battle_team_data[2560];
    
    // 偏移 4771-12450 (7680字节) - 营地角色数据
    struct {
        unsigned char data[80];
    } camp_characters[96];
    
    // 偏移 12451-12482 (32字节) - 营地图标缓存
    unsigned char camp_icon_cache[32];
    
    // 偏移 12483-12500 (18字节) - 营地游戏状态变量
    struct {
        unsigned char dword_53BEF;    // +0 (12483)
        unsigned char n6_0;           // +1 (12484) 角色数量
        unsigned char n17;            // +2 (12485) 当前地图ID
        unsigned char n9;             // +3 (12486)
        unsigned char n34;            // +4 (12487)
        unsigned char n9_0;           // +5 (12488)
        unsigned char n34_0;          // +6 (12489)
        unsigned char n2_2;           // +7 (12490)
        unsigned char n2_1;           // +8 (12491)
        unsigned char n7;             // +9 (12492) 图标数量
        unsigned int dword_53BF3;     // +10 (12493-12496)
        unsigned char byte_53AF9;     // +14 (12497)
        unsigned char byte_51AAB;     // +15 (12498)
        unsigned char n127;           // +16 (12499)
        unsigned char byte_51E62;     // +17 (12500)
    } camp_game_state;
    
    // 偏移 12501-12586 (86字节) - 未使用
    unsigned char unused[86];
    
    // ========== 战场临时存档区域 (12587 - 22982) ==========
    // 4个独立槽位，每个2600字节
    
    struct {
        unsigned char battle_data[2560];  // +0 战场画面数据
        unsigned char map_id;             // +2560 地图ID (0xFF表示空槽位)
        unsigned char icon_count;         // +2561 图标数量
        unsigned int dword_53BF3;         // +2562-2565
        unsigned char byte_51AAB;         // +2566
        unsigned char byte_53AF9;         // +2567
        unsigned char n127;               // +2568
        unsigned char byte_51E62;         // +2569
        unsigned char padding[30];        // +2570-2599
    } battle_save_slots[4];
    
    // ========== 校验和 (22983 - 22986) ==========
    unsigned int checksum;  // 前22983字节的累加和
    
} FD2_SAVE_FILE;
```

### 战场存档槽位位置计算

```c
// 槽位索引: n2_3 (0-3)
// 槽位起始位置: 12587 + 2600 * n2_3
// map_id位置: 12587 + 2600 * n2_3 + 2560

// 槽位0: 12587 + 2600 * 0 = 12587, map_id在 15147
// 槽位1: 12587 + 2600 * 1 = 15187, map_id在 17747
// 槽位2: 12587 + 2600 * 2 = 17787, map_id在 20347
// 槽位3: 12587 + 2600 * 3 = 20387, map_id在 22947
```

## 核心函数分析

### 1. sub_10010 - 加载营地存档

**地址**: 0x10010  
**大小**: 0x610 (1552字节)

**功能**: 游戏启动时读取并恢复营地存档

**流程**:
1. 分配22987字节缓冲区
2. 以"rb"模式打开 FD2.SAV
3. 读取整个22987字节到内存
4. 调用 sub_4DF28 解密
5. 调用 sub_4DF09 验证校验和
   - 如果校验失败: 显示错误信息 (ID 75)，进入标题画面
6. 从存档恢复数据:
   - 战场队伍数据: `memmove(dword_53BF7, v0 + 2211, 2560)`
   - 地图数据: `memmove(dword_53A55, v0, 2211)`
   - 角色数据: `memmove(dword_53A45, v0 + 4771, 80 * n6_0)`
   - 图标数据: `memmove(dword_53AD5, v0 + 12451, 32)`
7. 重新加载资源文件 (FDOTHER.DAT, FDFIELD.DAT, FDTXT.DAT, FDSHAP.DAT)
8. 处理 FDICON.B24 图标缓存
9. 恢复所有游戏状态变量 (偏移12483-12500)
10. 写入临时文件 FD2.TMP
11. 显示加载动画后进入游戏

**调用者**:
- sub_19DF7 (case 2: 读取存档, 0x1A251)
- sub_25EBB (v7 != 0 && v7 != 1时, 0x26130)

**关键代码片段**:
```c
// 0x1006A: 打开文件
v3 = fopen("FD2.SAV", "rb");

// 0x10082: 读取数据
sub_373CA(v0, 1, 22987, v3);  // fread

// 0x10099: 解密
sub_4DF28(v0, 22987);

// 0x100AD: 校验和验证
if (sub_4DF09(v0, 22987) != *(DWORD*)(v0 + 22983)) {
    // 校验失败处理
    sub_1956B(75);
    // ... 显示错误，进入标题画面
}

// 0x10121: 恢复战场队伍数据
memmove(dword_53BF7, v0 + 2211, 2560);

// 0x101CF: 恢复地图数据
v4 = memmove(dword_53A55, v0, 2211);

// 0x10311: 恢复角色数据
memmove(dword_53A45, v0 + 4771, 80 * n6_0);

// 0x10328: 恢复图标数据
memmove(dword_53AD5, v0 + 12451, 32);

// 0x103DF-0x10446: 恢复游戏状态变量
dword_53BEF = *(unsigned __int8 *)(v0 + 12483);
n6_0 = *(unsigned __int8 *)(v0 + 12484);
n17 = *(unsigned __int8 *)(v0 + 12485);
n9 = *(unsigned __int8 *)(v0 + 12486);
n34 = *(unsigned __int8 *)(v0 + 12487);
n9_0 = *(unsigned __int8 *)(v0 + 12488);
n34_0 = *(unsigned __int8 *)(v0 + 12489);
n2_2 = *(unsigned __int8 *)(v0 + 12490);
n2_1 = *(unsigned __int8 *)(v0 + 12491);
n7 = *(unsigned __int8 *)(v0 + 12492);
dword_53BF3 = *(_DWORD *)(v0 + 12493);
byte_53AF9 = *(_BYTE *)(v0 + 12497);
byte_51AAB = *(_BYTE *)(v0 + 12498);
n127 = *(_BYTE *)(v0 + 12499);
byte_51E62 = *(_BYTE *)(v0 + 12500);
```

### 2. sub_19DF7 - 存档菜单/保存营地存档

**地址**: 0x19DF7  
**大小**: 0x514 (1300字节)

**功能**: 处理存档菜单和保存营地存档

**流程**:
1. 尝试读取 FD2.SAV 检查是否存在
2. 显示存档菜单界面
3. 根据用户选择 (n2_3):
   - **case 0**: 进入营地场景 (sub_1B1E7)
   - **case 1**: 保存营地存档
   - **case 2**: 读取营地存档 (调用sub_10010)

**保存流程 (case 1)**:
1. 分配22987字节缓冲区
2. 读取现有存档 (如果存在)
3. 如果不存在，将4个战场存档槽位标记为无效 (设为0xFF)
   - `*(v19 + 15147) = -1`  // 槽位0的map_id
   - `*(v19 + 17747) = -1`  // 槽位1的map_id
   - `*(v19 + 20347) = -1`  // 槽位2的map_id
   - `*(v19 + 22947) = -1`  // 槽位3的map_id

4. 保存当前营地数据到缓冲区:
   - 地图数据: `memmove(v19, dword_53A55, 2211)`
   - 战场队伍数据: `memmove(v19 + 2211, dword_53BF7, 2560)`
   - 角色数据: `memmove(v19 + 4771, dword_53A45, 80 * n6_0)`
   - 图标数据: `memmove(v19 + 12451, dword_53AD5, 32)`
   - 游戏状态变量 (偏移 12483-12500)

5. 计算校验和: `*(DWORD*)(v19 + 22983) = sub_4DF09(v19, 22987)`
6. 加密: `sub_4DF28(v19, 22987)`
7. 写入: `fwrite(v19, 1, 22987, dst)`

**字符串引用**:
- 0x5016F: "FD2.SAV" (读取)
- 0x5017A: "FD2.SAV" (读取)
- 0x50185: "FD2.SAV" (写入)

**关键代码片段**:
```c
// 0x19F84: 分配缓冲区
v19 = malloc(22987);

// 0x19F95: 读取现有存档
v20 = fopen("FD2.SAV", "rb");
if (v20) {
    sub_373CA(v19, 1u, 22987, v20);
    sub_4DF28(v19, 22987);  // 解密
    fclose(v21);
} else {
    // 如果文件不存在，标记4个战场存档槽位为无效
    *(BYTE*)(v19 + 15147) = -1;
    *(BYTE*)(v19 + 17747) = -1;
    *(BYTE*)(v19 + 20347) = -1;
    *(BYTE*)(v19 + 22947) = -1;
}

// 0x19FF5-0x1A0DD: 保存营地数据
memmove(v19, dword_53A55, 2211);
memmove(v19 + 2211, dword_53BF7, 2560);
memmove(v19 + 4771, dword_53A45, 80 * n6_0);
memmove(v19 + 12451, dword_53AD5, 32);
*(BYTE*)(v19 + 12483) = dword_53BEF;
*(BYTE*)(v19 + 12484) = n6_0;
*(BYTE*)(v19 + 12485) = n17;
// ... 其他状态变量

// 0x1A102: 计算校验和并保存
*(DWORD*)(v19 + 22983) = sub_4DF09(v19, 22987);

// 0x1A10E: 加密
sub_4DF28(v19, 22987);

// 0x1A11F: 写入文件
fwrite(v19, 1, 22987, dst);
```

**注意**: 保存营地存档时，只更新前12501字节的共享数据区，不修改战场存档槽位的数据（除非文件是新建的）。

### 3. sub_25EBB - 游戏主入口/读取战场临时存档

**地址**: 0x25EBB  
**大小**: 0x297 (663字节)

**功能**: 游戏主入口函数，处理战场临时存档

**流程**:
1. 调用 sub_1F894 显示启动画面/菜单
2. 根据返回值判断:
   - **v7 == 0**: 新游戏
     - 初始化游戏状态
     - 调用对应地图的初始化函数 (funcs_25E3A[n17]())
   - **v7 == 1**: 读取战场临时存档
     - 分配22987字节缓冲区
     - 读取并解密 FD2.SAV
     - 如果文件不存在，全部填充为0xFF
     - 循环处理战场临时存档:
       - 调用 sub_29BCB 显示存档选择菜单
       - 从存档恢复战场数据 (2600字节)
       - 恢复战场状态变量
       - 如果map_id == 255，标记为无效，继续循环
     - 如果成功读取存档，调用 sub_26152 进入战场
   - **v7 != 0 && v7 != 1**: 调用 sub_10010 加载营地存档

**关键代码片段**:
```c
// 0x25FAB: 分配缓冲区
v10 = malloc(22987);

// 0x25FC1: 打开存档文件
LODWORD(v10) = fopen("FD2.SAV", &unk_50220);

if (v10) {
    sub_373CA(v8, 1u, 22987, v10);  // 读取
    sub_4DF28(v8, 22987);           // 解密
    fclose(v11);
} else {
    memset(v8, 255, 22987);  // 文件不存在，填充0xFF
}

// 0x2600C: 循环读取战场存档
n2_3 = 0;
do {
    v12 = sub_29BCB(v9, 0);  // 显示菜单，n2_3在菜单中被修改(0-3)
    if (v12 != -1) {
        // 0x26048: 计算当前槽位的起始位置
        v13 = (unsigned __int8 *)(v9 + 12587 + 2600 * n2_3);
        
        // 0x26056: 恢复战场数据
        memmove(dword_53BF7, v13, 2560);
        v13 += 2560;
        
        // 0x26067-0x26098: 恢复状态变量
        n17 = *v13;
        n7 = v13[1];
        dword_53BF3 = *(DWORD*)(v13 + 2);
        byte_51AAB = v13[6];
        byte_53AF9 = v13[7];
        n127 = v13[8];
        byte_51E62 = v13[9];
        
        // 0x260A7: 检查是否有效
        if (n17 == 255)
            v12 = 0;  // 标记为无效，继续循环
    }
    sub_26996();
} while (!v12);

// 0x260DC: 如果读取成功，进入战场
if (v12 == 1) {
    byte_51AAC = 0;
    v12 = sub_26152(v10, HIDWORD(v10));
    if (!v12) {
        funcs_25E3A[n17]();
        sub_25977(byte_51E63[n17], 0);
    }
    byte_51AAC = 1;
}
```

### 5. sub_2968D - 保存战场临时存档

**地址**: 0x2968D  
**大小**: 0x1E2 (482字节)

**功能**: 保存当前战场状态到临时存档

**流程**:
1. 分配22987字节缓冲区
2. 读取现有 FD2.SAV (如果存在)
3. 如果不存在，全部填充为0xFF
4. 显示存档选择菜单 (sub_29BCB)，获取槽位索引 n2_3
5. 计算当前槽位位置: `v11 = 2600 * n2_3 + v6 + 12587`
6. 保存当前战场数据:
   - 战场画面数据 (2560字节)
   - 战场状态变量 (n17, n7, dword_53BF3, byte_51AAB, byte_53AF9, n127, byte_51E62)
7. 计算校验和并加密
8. 写入 FD2.SAV
9. 检查地图是否已完成，如果已完成则显示提示

**调用者**:
- sub_26152 (0x26331)
- sub_29300 (0x2940E)

**关键代码片段**:
```c
// 0x296A0: 分配缓冲区

        v11 = 2600 * n2_3 + v6 + 12587;
```

### 6. sub_29BCB - 存档选择菜单

**地址**: 0x29BCB  
**大小**: 0x1DF (479字节)

**功能**: 显示存档槽位选择菜单

**流程**:
1. 分配3个64000字节的缓冲区用于画面处理
2. 复制当前屏幕数据
3. 调用 sub_29AB2 绘制存档菜单界面
4. 等待用户输入:
   - 上键 (72): 选择上一个存档槽，n2_3--
   - 下键 (80): 选择下一个存档槽，n2_3++
   - 回车/空格 (28/57): 确认选择，返回 1
   - Esc (1): 取消选择，返回 -1
5. **n2_3范围限制**: 0-3 (最大3，最小0)
6. 清理临时缓冲区

**调用者**:
- sub_25EBB (0x26021)
- sub_2968D (0x29712)
- sub_2986F (0x298EF)

**关键代码片段**:
```c
// 0x29BE1: 初始化
v6 = 0;  // 返回值
n2_3 = 0;  // 当前槽位索引

// 0x29D24: 下键处理
if (n28 == 80 || n2_3 == 3)  // 已经在最大槽位，不能再下
{
    // ...
}
else
{
    ++n2_3;  // 下一个槽位
}

// 0x29D60: 上键处理
if (n28 == 72 && n2_3)  // 不是第一个槽位
{

    v6 = 1;  // 返回1表示确认
}

// 0x29D96: 取消

{
    v6 = -1;  // 返回-1表示取消
}
```

**重要**: n2_3是全局变量，在菜单中被修改，用于标识当前选择的存档槽位（0-3）。

## 战场临时存档结构详解

每个战场临时存档槽位占2600字节：

```c
struct battle_save_slot {

    unsigned char battle_data[2560];  // 战场画面数据
    
    // +2560 (1字节)
    unsigned char map_id;  // 地图ID (0xFF表示空槽位)
    
    // +2561 (1字节)
    unsigned char icon_count;  // 图标数量
    
    // +2562 - +2565 (4字节)

    // +2567 (1字节)

    unsigned char byte_51E62;  // 状态字节
    
    // +2570 - +2599 (30字节)
    unsigned char padding[30];  // 未使用
};
```

## 实现要点

### 读写存档时的注意事项

1. **必须先解密再读取数据**:
   ```c
   fread(buffer, 1, 22987, fp);
   sub_4DF28(buffer, 22987);  // 解密
   // 现在可以访问数据
   ```

2. **写入前必须加密**:
   ```c
   // 填充数据
   *(DWORD*)(buffer + 22983) = sub_4DF09(buffer, 22987);  // 计算校验和
   sub_4DF28(buffer, 22987);  // 加密
   fwrite(buffer, 1, 22987, fp);
   ```

3. **校验和验证**:
   ```c
   if (sub_4DF09(buffer, 22987) != *(uint32_t*)(buffer + 22983)) {
       // 存档损坏
   }
   ```

4. **空槽位标记**:
   - 战场存档的 map_id 设为 0xFF 表示该槽位为空

5. **存档保护**:
   - 保存营地存档时，只更新前12501字节的共享数据区，不覆盖战场存档数据
   - 保存战场存档时，只更新对应的2600字节槽位区域，不覆盖营地存档数据

6. **存档槽位管理**:
   - n2_3是全局变量，范围0-3，表示当前选择的存档槽位
   - 战场存档位置计算公式: `12587 + 2600 * n2_3`
   - 战场存档map_id位置: `12587 + 2600 * n2_3 + 2560`

## 重要发现总结

### 1. 存档槽位机制
- **4个存档槽位** (n2_3 = 0, 1, 2, 3)
- 前12501字节是所有槽位**共享**的营地数据区
- 从12587开始是**4个独立**的战场存档槽位，每个2600字节

### 2. 数据保护机制
- 保存营地存档时：只更新前12501字节，保留战场存档数据
- 保存战场存档时：只更新对应的2600字节槽位，保留营地数据
- 新建文件时：标记所有4个战场槽位为无效

### 3. 文件结构
```
[共享营地数据 12501字节] [未使用86字节] [战场槽位0 2600字节] [战场槽位1 2600字节] [战场槽位2 2600字节] [战场槽位3 2600字节] [校验和4字节]
```
